# Customers

## Business Purpose
The central customer master registry — stores customer demographic information, trade name (`Name`), phone/mobile numbers, addresses, coordinates (`Latitude`, `Longitude`), tax registration (`TaxCardNo`), and status flags (`IsSuspended`). Serves as the primary reference table for customer lookups and identification across the system. Queryable via `t.Customers`.

## Chatbot semantics
(Query `t.Customers` — scoped by session CompanyID via `t.` views.)

| User / Arabic intent | Column(s) | Filter / rule | Notes |
|----------------------|-----------|---------------|-------|
| البحث عن زبون بالاسم | `Name` | `Name LIKE N'%...%'` | Arabic customer commercial name |
| رقم العميل | `ID` | `ID = ...` | Primary customer key (bigint) |
| عميل موقوف / فعال | `IsSuspended` | `IsSuspended = 0` (Active), `1` (Suspended) | Active commercial status |
| هاتف العميل | `Tel1`, `Mobile` | Direct select | Contact numbers |
| إحداثيات العميل المسجلة | `Latitude`, `Longitude` | GPS strings | Master store coordinates (compared with visit GPS) |
| رصيد وسقف ائتمان ومسار العميل | Join `t.CustomersFinancialDetails` | `c.ID = f.CustomerID` | Financial parameters live in `CustomersFinancialDetails` |

**Do not confuse with:**
- `CustomersFinancialDetails`: Stores route assignments, price lists, salesman links, and credit limits. `Customers` holds general master identity.
- `LogActionTransaction`: Action log of visits made to this customer.

## Grain & keys
- **PK**: `ID` (bigint customer code)
- **Tenant key**: `CompanyID`
- **FKs**: `PriceListID` → [[PriceLists]](ID), `CityID` → City codes

## Pipeline
Managed via Back Office customer screens (`Pro_Customers`) or ERP integration sync (`Balad_AddCustomer`, `Defaf_AddCustomer`). Synced to mobile devices.

## Common Issues

- **Duplicate customers**: Multiple records with same name/phone created during sync — support agent sees duplicate entries in dropdowns
- **Orphan references**: Customer records referenced by transactions that were soft-deleted — causes FK violation on cleanup
- **Balance mismatch**: CustomerBalance field diverges from actual calculated balance — run reconciliation proc
- **Suspend stuck**: IsSuspended flag not clearing after payment — check WF approval chain
- **GPS not collected**: IsCollectedGPS flag false — affects route optimization
